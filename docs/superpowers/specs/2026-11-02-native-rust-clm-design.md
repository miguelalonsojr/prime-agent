The saved TypeScript design is reference only where it agrees with that source. In particular, do not implement its absent target-specific audit-replay confirmation, schema-33 proposal or capability. The existing port stays commit `7d3c8d64367ca41931ff435aea06db5914062246`. CLM and its validated copy-only import support form the second final local commit. No installation, push, main merge, personal-session reads/imports, new dependencies or TypeScript application revival.

This is a full-path change because persistence, public daemon vocabulary and tool concurrency are involved. Parallelize independent work after fixing shared interfaces; use isolated writers, TDD, source parity, focused integration checks and independent reviews. The user explicitly opted to proceed instead of another question round. Internal planning/review does not authorize scope expansion.

## Source behavior

Retain `/clm on|off|status|view|restore <epoch:revision>`, `clm.enabled` global/project default for new sessions, persisted effective branch-local mode and its origin, isolated child inheritance, accepted read-only view and bounded revision history. Settings reload never switches an active session. No-op toggles write no boundary. Existing model tools edit the absolute session artifact `clm/context.txt`; do not add a model-facing tool.

Enable captures current model-visible context, including existing compaction, as revision zero of a new epoch. Off durably freezes a self-contained accepted snapshot plus audit watermark; future normal context starts there. Later enable starts a new epoch from current reconstructed context. Restore is on-only, current-epoch and selected-ancestor only, and appends a new revision with current watermark. Audit entries remain immutable and inspectable. Source behavior permits explicit navigation/fork to pre-CLM ancestry after off without the design-only consent flag; subsequent enable then uses that selected context. Never claim secure deletion or permanent exclusion from arbitrary historical branches.

The editable document uses existing durable message IDs and roles. Protected active user/steering actions cannot be changed until the action settles. Fake control headers are inert. Images resolve only to the original block's registry. Complete unchanged native tool groups retain their structure; edited/rearranged tool groups become historical text. Accepted snapshot corruption, unavailable recovery or unknown writer ownership blocks model requests; never fall back to covered audit text. Source caps: 32 MiB editable document and 512 MiB durable snapshot. Oversized accepted read-only views do not weaken edit/provider limits.

At each provider request, estimate fixed instructions/tools, projected messages/images and output reserve. Reject over-budget requests and edits before dispatch. At 75% estimated input occupancy add a request-only reminder targeting below 60%, skipping it if it would itself exceed budget. This is not billed usage. Observed provider receipts pin branch/mode/epoch/revision at dispatch; missing/unfinished/unrecognized receipts are unknown, not zero. Preserve existing audit totals and do not fold child totals into one revision subtotal.

CLM-on blocks manual/automatic/overflow compaction, historical navigation/fork and side questions wherever those operations exist natively. Do not add absent TS extension infrastructure. New children inherit the effective mode once and own their own context/artifacts. An active parent writer admits a child only with runtime-verified origin bound to the live tool action. Child accounting may append only an ordered `child_usage_attributed` suffix while retaining the captured leaf on the active ancestry; other journal mutations still conflict.

## Native ownership

Shared serialized CLM vocabulary belongs in `pa-types`. Pure document, budget, snapshot validation and branch-projection rules belong in a focused `pa-core::clm` module. Core SessionManager and worker SessionFile must call the same projection policy, not independently encode its rules. The daemon worker remains the durable journal owner for daemon sessions; the standalone SessionManager retains its existing ownership. Accepted state lives in native JSONL rows, not a new transcript database. Working text and writer marker are session artifacts, not authorities for accepted context.

The session-engine/tool hooks own lifecycle state, protected action identities, provider projection and request usage pins. A provider may consume a new accepted snapshot only after its durable commit acknowledgement. Unknown/cancelled writers remain locked. Native exposes only python_repl, not the separate recognized TypeScript edit tool. Cancelled Python/bash/custom, including a Python edit-skill call, stays blocked; early public abort responses and Python Done are not repair authority. The source positive recognized-edit repair path has no native producer and is inapplicable; do not add a new tool or pretend to implement its receipt. Do not infer settlement from time, empty queues or unchanged hashes. Mode/restore/view capture under the native session action and persistence fences; read-only view never imports pending file bytes. Atomic mirror publication and file/directory fsync failures reject mutation with the last accepted projection retained.

The native daemon and TUI exchange the source commands `get_clm_status`, `set_clm_mode`, `restore_clm_revision`, and `get_clm_model_snapshot`, gated by protocol 7, schema revision 32 and capability `clm_context_v1`. Update the native schema ID through its normal consistency rule. Old-daemon `/clm` errors locally before any unsupported write, while attach and ordinary operations remain usable. Optional CLM inspection failure stays local. TUI renders wire data only; no engine dependency or disk/network await on its paint path. Required adoption telemetry is primitive-only and fire-and-forget.

Reuse existing `import_jsonl` and TUI import, not a new command. Strengthen only the CLM import path: validate source CLM rows, selected ancestry, accepted snapshots, usage/images and version before publishing a Rust-owned copy. Never overwrite the source or an existing destination, and never import pending working-file edits or live Python state. Fresh copy identity/artifact ownership and strict rejection behavior are specified in the final interface plan. Ordinary non-CLM imports retain their existing behavior.

## Frozen interfaces and ownership

`pa-types::clm` owns source-shaped DTOs. `ClmBlock { id: String, message: serde_json::Value }` is an owned semantic helper, not the checksum serialization authority. `ClmSnapshot` is a serde-transparent immutable wrapper over the WHOLE ordered raw `serde_json::Value`, with a private inner field and `from_value(Value) -> Self`, `as_value(&self) -> &Value`, `into_value(self) -> Value`, `from_blocks(Vec<ClmBlock>) -> Self` helpers. Structural/policy validation stays in pa-core. Pure policy may inspect raw block Values by reference or make helpers, but unchanged parsed blocks preserve their original raw JSON. A changed document constructs a fresh `{blocks}` snapshot from raw returned blocks in source order. Preserve block-field and top-level unknown-field order too, not only nested message keys. Never keep independently mutable typed blocks alongside a stale raw snapshot; never serialize semantic message helpers over imported raw data. Common `ClmBoundary { epoch_id: String, revision: u64, snapshot: ClmSnapshot, audit_watermark: Option<String> }`; FileEntry variants `ClmOn { payload: ClmOnEntry, base: EntryBase }`, `ClmRevision { payload: ClmRevisionEntry, base: EntryBase }`, `ClmOffBoundary { payload: ClmOffBoundaryEntry, base: EntryBase }` use existing flatten/camelCase conventions. On/off payloads flatten boundary plus optional modeSource; revision adds baseRevision/checksum/observedActionId. Malformed recognized CLM rows must retain a fatal CLM error, never become ordinary unknown rows that permit raw-history replay. Do not change unrelated unknown-row behavior.

`ClmMode` serializes on/off. Persisted `ClmModeSource` serializes configured-default/inherited-child/session-override; use a separate status-source value or optional field mapping for unknown, never persist an invented unknown source. `ClmRevisionRef { epoch_id, revision }`, `ClmUsagePin { mode, branch_id: Option<String>, epoch_id: Option<String>, revision: Option<u64>, entry_id: Option<String> }` mirror source. `ClmRequestBudget { estimated_input_tokens: u64, output_reserve_tokens: Option<u64>, max_input_tokens: Option<u64> }` uses the existing native Model's integral context_window/max_tokens; do not expand Model to fractional values. Text accounting uses JavaScript UTF-16 length, not Rust UTF-8 bytes. `ClmStatus` has exact source wire fields: modeSource/recentRevisions/configuredDefault/mode/optional epochId/revision/path:string/optional estimatedOccupancy/warning/error/measuredUsage. `ClmMeasuredUsage` is numeric input/output/cacheRead/cacheWrite/cost, not the nested billing-cost type. `ClmAcceptedView { epoch_id: String, revision: u64, messages: Vec<Value> }` keeps accepted messages lossless. No new accepted/budget nested status format.

Pure `pa-core::clm` exports:
- `type ProtectedActions = BTreeMap<String, Vec<ClmBlock>>`.
- `render_context_document(snapshot: &ClmSnapshot, protected_ids: &HashSet<String>) -> Result<String, ClmError>` and `parse_context_document(text: &str, base: &ClmSnapshot) -> Result<ClmSnapshot, ClmError>`.
- `validate_protection(candidate: &ClmSnapshot, actions: &ProtectedActions) -> Result<(), ClmError>`.
- `snapshot_checksum(snapshot: &ClmSnapshot) -> Result<String, ClmError>`: SHA-256 of source JSON.stringify semantics, proved by synthetic key-order/number goldens. Existing preserve_order and sha2 suffice; no global JsNumber refactor/dependency.
- `estimate_clm_request_tokens(messages: &[Value], system_prompt: &str, tools: &[pa_types::ai::Tool], model: &pa_types::ai::Model) -> Result<ClmRequestBudget, ClmError>`; source role conversion, fixed/tool/image/output-reserve costs; opaque raw parameters stay ordered.
- `validate_clm_branch(branch: &[FileEntry]) -> Result<ClmBranchState, ClmError>` on a complete selected ancestor path; `validate_child_usage_suffix(branch: &[FileEntry], captured_leaf: Option<&str>) -> Result<(), ClmError>`. Historical branch validation does not enforce the cumulative new-write cap.
- `validate_clm_snapshot_admission(entries: &[FileEntry], candidate: &ClmSnapshot) -> Result<(), ClmError>` counts the candidate once plus every stored on/revision/off snapshot once across the complete session file, using UTF-8 bytes of source JSON.stringify semantics. Equality with 512 MiB is allowed; overflow or a larger total is a budget error.
- `project_clm_branch(branch: &[FileEntry]) -> Result<Option<ClmProjection>, ClmError>` where None means no CLM on this selected ancestry, never a corrupt/unknown/truncated boundary. `ClmProjection` contains source branch state, ordered projected blocks and current watermark. Frozen off-boundary projection uses existing normal compaction semantics over the accepted seed and uncovered suffix; normal no-CLM fold remains unchanged, not duplicated or recursively called through the CLM wrapper.
- `validate_clm_import(bytes: &[u8]) -> Result<Option<ValidatedClmImport>, ClmError>`; None for ordinary non-CLM input. Result has validated entries/source session identity; validate every CLM branch, ancestry/checksum/roles/images, safe IDs and parse-damage evidence. No I/O or destination creation in this pure validator.
- `get_clm_measured_usage(branch: &[FileEntry]) -> Result<Option<ClmMeasuredUsage>, ClmError>` consumes the complete selected branch. Task3 owns this single pure fold in `clm/usage.rs`; Task4 calls it on the acknowledged journal view. Invalid branch state stays fatal. Unknown, missing, unsupported or unattributed matching usage stays unknown. The subtotal excludes child totals and follows source revision/entry/branch pins.

`ClmError` distinguishes invalid document/protection, budget, journal conflict, unresolved/unknown writer and persistence uncertainty. CLM safety failures are not transient provider failures. Constants stay 32*1024*1024 editable UTF-8 bytes and 512*1024*1024 CUMULATIVE serialized accepted snapshots, 0.75 warning threshold, 0.60 target.

The sole new embedding seam is in `pa-core::clm::journal`, independent of daemon/controller implementations:
```
ClmJournalView { generation: String, session_id: String, leaf_id: Option<String>,
    branch: Vec<FileEntry>, protected: ProtectedActions }
ClmCommit { expected: ClmJournalView, row: FileEntry, allow_child_usage_suffix: bool }
ClmJournalOp = ReadAfterEvents | Commit(ClmCommit)
ClmJournalReply = View(ClmJournalView) | Committed { row: FileEntry, view: ClmJournalView }
ClmJournalFn = Arc<dyn Fn(ClmJournalOp) -> BoxFuture<'static, anyhow::Result<ClmJournalReply>> + Send + Sync>
```
Use the workspace's existing boxed-future type/path, not a new dependency. The callback acknowledges authoritative worker audit rows before returning. Check generation, selected ancestry, revision and allowed accounting suffix under the existing writer lock; append/sync before publishing success. No lock required by acknowledgement may be held while awaiting it. Adopt returned exact row IDs in the core mirror without a second write. Direct SessionManager and daemon SessionFile each implement their existing ownership, not two owners in one session.

Both owners enforce `validate_clm_snapshot_admission` from their complete entry collection inside the existing commit boundary, after comparison and before durable or in-memory mutation. This covers on, changed edit, off, restore and failed-provider cleanup. A cap rejection is deterministic and must not poison the owner as an uncertain write. The cap is not a storage-format invariant: readonly projection, reopen, status, import of structurally valid existing history and no-op operations do not admit a new snapshot and do not apply it. Keep all structural/checksum/ancestry validation and real persistence-uncertainty behavior. Do not expand `ClmJournalView`, cache a partial total or sum ancestry paths multiple times.

`pa-core::clm::controller::ClmController` is built from journal callback, session-file identity (optional in-memory session) and artifact directory. Its methods are async `project_request() -> Result<ClmProjection>`, `prepare_tool(tool_call_id: &str) -> Result<()>`, `settle_tool(tool_call_id: &str, outcome: ClmToolOutcome, inputs: &ClmRequestInputs) -> Result<()>`, `set_mode(enabled: bool, source: ClmModeSource) -> Result<ClmStatus>`, `restore(target: ClmRevisionRef) -> Result<ClmStatus>`, `status(configured_default: bool) -> Result<ClmStatus>`, `accepted_view() -> Result<ClmAcceptedView>`; synchronous `cancel_tool(tool_call_id: &str)` invalidates an in-progress read, `record_request_estimate(&self, estimate: ClmRequestBudget)` updates diagnostic occupancy/warning only, and `require_off(operation: &str) -> Result<()>` enforces authoritative guards. `ClmRequestInputs { system_prompt: String, tools: Vec<ai::Tool>, model: ai::Model }`; `ClmToolOutcome = Completed | Aborted | Unknown`. Retain one lane and source writer-marker semantics, not a generic transaction framework.

`project_request()` is a model-independent writer/protection/ancestry-checked projection. Its return does not authorize provider dispatch without the final request guard. Edit acceptance uses the inputs supplied to `settle_tool`. Task6 separately estimates the actual per-attempt target and final outgoing request, rejects excess input and adds the source request-only reminder only when it fits. It reports the base estimate before rejection and the reminder-inclusive estimate only when retained. `record_request_estimate` mirrors source `recordRequestEstimate`: it stores no model/request inputs, persists no rows and grants no request authorization. Its warning is "CLM context is near its request budget; shorten stale history" at the source threshold, and absent below it or with unknown max input.

The controller also provides `pub(crate) async fn discard_failed_provider_entry(&self, failed_entry: &ClmBlock) -> Result<()>`. Task4 owns this operation. Task6 supplies the canonical failed block from its acknowledged assistant append and keeps that request's delivery/action ownership live until cleanup settles. The controller obtains nonempty `ProtectedActions` from the acknowledged journal view. This adds no journal operation, public wire API, model tool or receipt type.

Cleanup uses the existing controller lane and requires healthy accepted state, an idle settled writer and no mirror drift. It verifies the exact last uncovered projected block by ID and complete message, requires assistant role and error stop reason, and rejects a target already present in the accepted snapshot. Non-message audit entries may follow the failed row. The candidate retains the accepted blocks and all other eligible uncovered blocks. Any other uncovered failed assistant or remaining pending tool group rejects cleanup. Protection and the editable document limit still apply.

The new same-epoch revision uses the next revision/base revision, the failed row ID as audit watermark and `failed-provider:<id>` as observed action. Cleanup commits with the captured expected view and `allow_child_usage_suffix: false`; new rows or changed ownership after capture must reject it. The existing owner enforces full-history snapshot admission and returns the authoritative row and view. The controller adopts that acknowledgement and publishes the confirmed snapshot through its existing atomic mirror path. Post-commit publication failure repairs only from the confirmed revision and blocks further model work if repair fails. Cleanup never rolls back an authoritative revision, imports rejected bytes, manufactures a usage receipt or requires request-budget inputs. Task6 retains the cleanup/recovery gate on failure and does not repin an observed provider receipt to the cleanup revision. Projection and tool preparation reject an uncovered failed provider entry without owned cleanup, including through a fresh controller after reopen.

Task6 adds one controller-local operation: `pub(crate) async fn assert_child_admission_available(&self, origin_action_id: Option<&str>) -> Result<(), ClmError>`. It uses the existing lane and acknowledged `ReadAfterEvents` view. It rejects owner uncertainty, changed controller session/generation or accepted state, and existing conflict. With no supplied origin it requires an idle writer and no marker; this permits healthy idle admission with CLM on or off. With an origin it requires the exact live owned action, unchanged cancellation generation and the armed marker still present as a regular file. Cancellation can run during the journal await, so ownership and marker checks must also hold after it. Existing marker/conflict failure semantics remain. The method neither parses nor publishes working context, commits a row, captures a usage pin, nor admits a snapshot. It must not apply the full `action.expected` commit comparator: ordinary audit suffixes such as `tool_started` do not invalidate child admission when accepted state and writer ownership remain healthy. Existing edit/commit comparison rules remain unchanged.

The runtime supplies child provenance, not the controller. At host-request admission it captures a fence instance bound to the manager-verified origin before preparatory awaits. Reused tool-call strings must not let an older request borrow a newer fence. It passes an action ID only while that captured instance is still the current live fence; otherwise the controller must authorize the ordinary idle branch. Payload fields and diagnostic status cannot grant ownership. The initial controller check and one authoritative effective-mode capture share the parent session-action fence. The necessary native journal await must not hold a journal-owner lock or any lock needed to acknowledge it, and the parent fence must preserve the initial identity/mode capture. Save the Boolean once before name/model/auth or child-create preparation awaits. Later checks validate current admission, not equality with that saved mode; they never resnapshot it or reread a default. Reject pending failed-provider cleanup or recovery before child work.

Revalidate after preparatory awaits and at the native logical child-registration boundary. If native child creation still awaits provisioning before registration, recheck before registration and handle return; a failure uses existing best-effort cleanup for only that provisional child. This does not promise that no provisional session existed or that cleanup cannot fail. If registration precedes runtime construction, later cancellation is an admitted-child lifecycle event. Neither ordering adds a post-admission retraction guarantee. Pass the saved internal `inherited_clm_mode`, including explicit false, to the new child's own journal/epoch/artifact. Existing children remain unchanged. This adds no journal operation, schema, model-facing field, recognized edit tool or receipt framework. If exact execution/fence correlation cannot be established with the trusted native metadata, report that gap rather than weaken the check or silently extend the kernel contract.

Physical provenance is a separate native kernel contract, usable without importing CLM: optional top-level host-frame `cell_id`; optional trusted `tool_call_id` on KernelExecuteOptions/ExecuteOptions; `HostRequestPayload { data, verified_tool_call_id: Option<String>, verified_tool_execution_identity: Option<ToolExecutionIdentity> }`. Only the manager can mint verified_tool_call_id after matching its live, noninternal, unsettled, nonaborted healthy cell. Detached/stale/forged data cannot authorize a later action. Structured ExecuteStatus::Aborted must reach the session integration through an optional trusted callback before flattening the tool result. Python Done is not permission to repair a cancelled writer. There is no separate recognized native edit tool: no positive cancelled-edit repair API is added. Cancelled Python/bash/custom, including the Python edit skill, remains blocked and restore cannot clear its marker.

Task6 extends that trusted native handoff with an opaque `ToolExecutionIdentity(Arc<()>)` in `kernel/shared.rs`. Its field is private; minting and `same_instance` are crate-internal, using `Arc::ptr_eq`, not value equality. It is cloneable/debuggable but not serializable and has no `PartialEq` or `Default`. One identity belongs to one successfully prepared runtime action fence; busy-kernel retries retain it. Add optional `tool_execution_identity` to `KernelExecuteOptions` and `ExecuteOptions`. The existing `ActiveExecution` owns the latter. Provider tool IDs and model-facing IDs remain unchanged.

One crate-internal Tokio task-local `Option<ToolExecutionIdentity>` transports that already-bound identity only over the inner tool execution future. Off/no-owned-action paths scope `None`; scope exit, error and cancellation restore the prior context. This is not a registry, a default identity or an authority source for unrelated spawned work. Built-in `execute_ipython` captures the fixed value before its first await and passes it through its existing kernel options and busy-retry path. `KernelManagerExecutor` copies it into the manager options. Internal/unowned executions carry no owned-writer privilege. No new embedding callback, Python field, public wire field, journal operation or dependency is added.

The manager copies the provider ID and identity from the same verified physical execution at host-frame receipt, before spawning asynchronous handling. Its old clone-active-then-check-buffers sequence is insufficient: rejection can clear the active slot without marking those buffers settled. Clone the candidate under `guarded`, release that guard, then lock candidate `buffers` followed by `guarded`. Recheck active-execution pointer identity and the existing cell/public/namespace/healthy/unsettled/abort predicates, and copy both trusted values within that check. Preserve the existing `buffers -> guarded` nested order used by settlement. Do not invoke handlers, runtime code or journal callbacks under either lock. The check establishes a valid instant, not continued physical liveness after the locks are released.

At runtime admission, a supplied identity can select only the exact current fence with matching provider ID and opaque instance. It never grants authority by itself; the controller gate and later captured-fence checks still apply. A delayed A request cannot borrow same-ID B. If a request was verified during A and the same healthy A fence remains while A settles after Done, do not add a handler-time physical-live requirement. If that fence is no longer current, use the existing idle branch, not B's identity. Keep one inherited-mode capture and the registration rules above. Test the real built-in Python/manager/host-bridge path with a barrier before handler capture, A Done, and same-ID B; also test B's own request, same-A settling, clone/reject interleaving, forged/untrusted metadata, and task-local isolation/restoration. These tests do not replace real-child inheritance/artifact proof or public CLI verification.

The runtime integration owns all engine/worker cross-calls together, including exact delivered row IDs and action lifetimes, acknowledgement-bearing channel events, controller wiring, actual-provider-model budget guard, provider usage receipts, failure cleanup, inherited child mode snapshot and guards. This is deliberately one later task: separate workers must not guess opposite halves of that protocol. Wire/UI can be prepared separately against the DTOs, but the server advertises clm_context_v1 only when the working backend lands. No production stub or optimistic capability.

## Rejected alternatives and decisions

Reintroducing TS or a second transcript store violates the native port. Using after_tool_call as physical settlement violates the pinned abort contract. Reusing ordinary best-effort session emissions cannot prove durability. Hashing typed reserialization or sorted canonical JSON breaks imported checksums. A new import command duplicates an existing surface. The user rejected adding the unimplemented audit-replay confirmation. These are excluded, not future tasks hidden in this commit.
