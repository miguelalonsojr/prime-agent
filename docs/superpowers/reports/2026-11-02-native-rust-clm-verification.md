## Coverage caveats

- Intent 0: production attach reads raw audit messages independently of CLM status and accepted-snapshot queries. A mock shows failure isolation, but not an identical TypeScript reconnect adapter.
- Intent 25: native cases compose two child rows during an edited action, persisted aggregation and accepted-body reopen. No single test asserts the source's `[3,5]`, final 8, revision, watermark and edited body after reopen in one scenario. A combined test would strengthen evidence but is not a required gap.
- Intent 26: native publication pauses after capture and before validation, not at the same TypeScript post-rename await point. No separate native actor mutates the captured state during rename.
- Intent 37: accepted-body iterative summaries and no-tail/real-tail synthetic cases are covered by corresponding native cases, not a TypeScript suite pass.

CLM admission counts the candidate snapshot once plus all stored on/revision/off snapshots once using source-compatible JSON UTF-8 bytes. Equality at 512 MiB is allowed. This is an admission cap, not a general read/reopen/import quota. The 32 MiB editable-document cap and provider request budget are separate. The immutable audit retains original rows even when accepted model context removes them. Retained tool code may also repeat the text. CLM does not promise secure or global erasure. Final workspace-green, cross-platform and install-ready claims remain unsupported.
